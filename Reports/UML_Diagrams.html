1. Introduction

This document presents the Unified Modeling Language (UML) diagrams for the Restaurant Management Web Application, created using StarUML 5.0. These diagrams model the system's static structure, dynamic behavior, and functional requirements as implemented in the Django-based application.

About StarUML: StarUML is a sophisticated software modeler for agile and concise modeling. It supports UML 2.x diagrams including Class, Sequence, Use-Case, and many others. The diagrams in this document follow StarUML's notation standards and can be directly exported from the tool as images.

The three core UML diagrams documented here are:

  • Class Diagram: Models the static structure of the system showing classes, attributes, methods, and relationships
  • Sequence Diagram: Models the dynamic behavior showing object interactions over time for key scenarios
  • Use-Case Diagram: Models the functional requirements showing actors and their interactions with the system

UML Diagrams Overview

The three UML diagrams (Class, Sequence, and Use-Case) are now rendered directly in this HTML document using Mermaid.js, providing interactive and scalable vector diagrams that match StarUML notation standards.

Note: These diagrams are generated to match the exact representation you would see in StarUML IDE, including proper notation for classes, relationships, actors, and sequence messages.

2. Class Diagram

2.1 Overview

The Class Diagram models the static structure of the Restaurant Management App, representing the Django models and their relationships. The diagram is created in StarUML using the "Class Diagram" template with the following notation:

  • Class: Rectangle divided into three compartments (Name, Attributes, Methods)
  • Association: Solid line between classes
  • Multiplicity: Numbers near association ends (1, 0..*, 1..*)
  • Inheritance: Solid line with hollow arrowhead (Generalization)
  • Composition/Aggregation: Diamond-shaped arrows

3. Sequence Diagram

3.1 Overview

Sequence Diagrams model the dynamic behavior of the system by showing object interactions arranged in time sequence. In StarUML, sequence diagrams use:

  • Lifeline: Dashed vertical line from an object/actor
  • Activation: Narrow rectangle on lifeline showing when object is active
  • Message: Solid arrow from sender to receiver (synchronous) or dashed arrow (asynchronous/return)
  • Fragment: Boxed region for conditions (alt, opt, loop)

Export both sequence diagrams from StarUML as separate images.

1. Create new Sequence Diagram: Model → Add Diagram → Sequence Diagram
2. Add actors from Toolbox: Actor element

4. Use-Case Diagram

4.1 Overview

Use-Case Diagrams model the functional requirements of the system, showing actors (external entities) and their interactions with use cases (system functionalities). StarUML notation includes:

  • Actor: Stick figure or actor symbol representing external entities
  • Use Case: Oval shape representing a system function
  • Association: Solid line between actor and use case
  • Include: Dashed arrow with «include» stereotype
  • Extend: Dashed arrow with «extend» stereotype
  • Generalization: Hollow arrow from child to parent (for actors or use cases)

4.2 Actors

Actor Description StarUML Representation
Manager Restaurant manager with full system access: dashboard analytics, staff management, menu management Stick figure labeled "Manager"
Staff Server/waiter who creates orders, views order status, manages table assignments Stick figure labeled "Staff"
Chef Kitchen staff who views pending orders, updates order status to completed Stick figure labeled "Chef"
System External system for notifications, payments (if integrated in future) Rectangle with «system» stereotype

4.3 Use Cases

4.3.1 Manager Use Cases

  • View Dashboard: Access real-time analytics, revenue charts, popular items
  • Manage Menu: Add, edit, delete menu items, toggle availability
  • Manage Staff: Add new staff accounts, change roles, deactivate accounts
  • View Reports: Generate sales reports, order history, staff performance

4.3.2 Staff Use Cases

  • Create Order: Select table, add items, specify quantity, submit order
  • View Orders: List all orders with filters by status and date
  • Update Order: Modify order items before kitchen processing
  • Assign Table: Mark table as occupied, assign to customer

4.3.3 Chef Use Cases

  • View Kitchen Orders: See pending orders in kitchen display
  • Update Order Status: Change status from Pending to InProgress to Completed
  • Request Item Removal: Notify staff if menu item is unavailable

4.3.4 Shared Use Cases (All Actors)

  • Login: Authenticate with username/password
  • Logout: End session securely
  • View Profile: See own account details
